# tests/

## Layout
- `unit/`: one rule or function per test; name tests after the behaviour (`test_city_requires_own_settlement`).
- `property/`: `hypothesis` tests for invariants (list in `property/README.md`).
- `conformance/`: golden replays (seed + actions -> state hashes). Language-neutral; the Rust port must pass them. Generated by tooling, never edited by hand.

## Conventions
- Tests first: write the failing test, show it failing, then implement.
- Every rule test cites its rule, e.g. `# rules-spec 4: discard half, rounded down`. Edge cases also get a row in the `rules-spec.md` section 10 table.
- Build states through engine helpers or `step`, not by hand-assembling fields, so tests survive `GameState` changes.
- Property tests: seed every source of randomness through hypothesis strategies, keep examples small by default, and put slow ones behind a `slow` marker.
- No test may depend on wall-clock time, network or test execution order.

## Commands
- All: `uv run pytest -q`
- One file: `uv run pytest tests/unit/test_smoke.py -q`
